# Шпаргалка к защите — задание №4

## Главное в двух словах
- **PostgreSQL** — основная база данных, там данные хранятся надёжно (на диске).
- **Redis** — быстрый кэш в оперативной памяти. Список товаров кладём туда, чтобы не ходить в БД при каждом запросе.
- **Docker** — каждый сервис (backend, postgres, redis) работает в своём контейнере. **Docker Compose** запускает их все одной командой.

## Вопросы и ответы

### База данных и кэш

**Зачем основная БД, если есть Redis?**
PostgreSQL хранит данные постоянно и надёжно. Redis — временная копия для скорости: данные в нём живут ограниченное время (TTL) и могут быть удалены в любой момент.

**Что такое Redis?**
Хранилище «ключ → значение» в оперативной памяти, поэтому очень быстрое. У нас ключ `products:all`, значение — список товаров в виде JSON-строки.

**Как работает кэширование `GET /api/products`?** (файл `src/index.js`)
1. Ищем ключ `products:all` в Redis.
2. Если есть — отдаём из кэша (`X-Cache: HIT`).
3. Если нет — делаем `SELECT` в PostgreSQL, сохраняем результат в Redis на 60 секунд и отдаём (`X-Cache: MISS`).

**Что такое TTL?**
Time To Live — время жизни ключа. Через 60 секунд Redis сам удалит кэш (`{ EX: CACHE_TTL }`), и следующий запрос пойдёт в БД.

**Зачем очищать кэш при создании, изменении и удалении?**
Иначе Redis отдавал бы старый список без новых изменений. После POST, PATCH или DELETE вызываем `redis.del('products:all')`.

**Зачем `$1, $2` в SQL-запросах?**
Это параметры: значения передаются отдельно от текста запроса, что защищает от SQL-инъекций.

**Где создаётся таблица?**
В `src/db.js`: при старте выполняется `CREATE TABLE IF NOT EXISTS products (...)`. Поле `created_at` заполняется автоматически (`DEFAULT NOW()`).

### Docker

**Что такое Docker и контейнер?**
Docker запускает программы в изолированных **контейнерах** со всем нужным окружением. Приложение работает одинаково на любом компьютере.

**Образ и контейнер — в чём разница?**
Образ — шаблон (как установочный диск). Контейнер — запущенный экземпляр образа.

**Что делает Dockerfile?**
Описывает, как собрать образ backend:
1. `FROM node:22-alpine` — берём образ с Node.js;
2. `WORKDIR /app` — рабочая папка;
3. `COPY package*.json` + `RUN npm install` — устанавливаем зависимости;
4. `COPY src` — копируем код;
5. `EXPOSE 3000` — порт приложения;
6. `CMD ["node", "src/index.js"]` — команда запуска.

**Зачем копировать сначала package.json, а потом код?**
Docker кэширует шаги сборки. Если менялся только код, `npm install` не выполняется заново, и сборка быстрее.

**Что такое Docker Compose?**
Инструмент, чтобы описать несколько контейнеров в одном файле `docker-compose.yml` и запустить их командой `docker compose up --build` (`--build` — пересобрать образ backend).

**Что описано в docker-compose.yml?**
- `backend` — собирается из Dockerfile, порт 3000;
- `postgres` — готовый образ PostgreSQL;
- `redis` — готовый образ Redis;
- `networks` — общая сеть;
- `volumes` — хранилище данных БД.

**Как контейнеры находят друг друга?**
Все подключены к сети `app-network`. Внутри сети имя сервиса работает как адрес: backend подключается к БД по адресу `postgres`, к кэшу — `redis://redis:6379`.

**Что такое переменные окружения и зачем они?**
Настройки, которые передаются программе снаружи, а не пишутся в коде: `DB_HOST`, `DB_PASSWORD`, `REDIS_URL` и т.д. Задаются в `environment` в docker-compose.yml, в коде читаются через `process.env.DB_HOST`. Так одно и то же приложение можно запустить с разными настройками без изменения кода.

**Что такое Docker Volume?**
Хранилище данных вне контейнера. Контейнер можно удалить, а volume `postgres-data` (подключён к папке с данными PostgreSQL) останется. Поэтому после `docker compose down` и `up` товары не пропадают.

**Что значит `ports: "3000:3000"`?**
`порт_на_компьютере:порт_в_контейнере` — открывает порт контейнера наружу, чтобы обращаться к нему с компьютера.

**Зачем `depends_on` и `healthcheck`?**
`healthcheck` проверяет, что PostgreSQL и Redis готовы к работе. `depends_on` с `service_healthy` запускает backend только после этого. Дополнительно `db.js` повторяет попытки подключения.
