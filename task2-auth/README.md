# Задание №2 — Аутентификация, JWT и роли

Сервер на **Express** с регистрацией, входом и ролями, клиент на **React**.
Пароли хешируются через **bcrypt**, при входе выдаётся **JWT access-токен**.

**Роли:**
- `user` — обычный пользователь: только просматривает товары;
- `employee` — сотрудник: просматривает, создаёт, изменяет и удаляет товары.

## Структура

```
task2-auth/
├── server/
│   ├── index.js       — маршруты: регистрация, вход, /me, товары
│   └── middleware.js  — проверка токена (authMiddleware) и роли (roleMiddleware)
└── client/src/
    ├── App.jsx        — показывает форму входа или товары
    ├── AuthForm.jsx   — вход и регистрация
    ├── Products.jsx   — список товаров и управление ими
    └── api.js         — запросы к серверу, токен в заголовке Authorization
```

## Запуск

**Терминал 1 — сервер:**
```bash
cd task2-auth/server
npm install
npm start
```

**Терминал 2 — клиент:**
```bash
cd task2-auth/client
npm install
npm run dev
```
Открыть http://localhost:5173

> Пользователи хранятся в памяти: после перезапуска сервера нужно зарегистрироваться заново.

## API

| Метод | Адрес | Доступ |
|---|---|---|
| POST | `/api/auth/register` | все |
| POST | `/api/auth/login` | все → возвращает `accessToken` |
| GET | `/api/auth/me` | с токеном |
| GET | `/api/products`, `/api/products/:id` | с токеном (user, employee) |
| POST / PATCH / DELETE | `/api/products...` | только `employee` |

## Что показать на защите

1. **Регистрация:** вкладка «Регистрация» → `user@test.ru` / `123456`, роль «Обычный пользователь». Затем `emp@test.ru` / `123456`, роль «Сотрудник».
2. **Вход** под `user@test.ru`.
3. **JWT-токен:** F12 → вкладка **Application** → **Local Storage** → `http://localhost:5173` → ключ `accessToken`. Можно вставить токен на https://jwt.io и показать, что внутри id, email и role.
4. **Защищённый маршрут:** F12 → вкладка **Network** → обновить страницу → запрос `me` → в заголовках запроса виден `Authorization: Bearer ...`, в ответе — данные пользователя.
5. **Отказ сервера:** под пользователем нажать «Попробовать добавить товар (проверка прав)» → сообщение «Сервер отказал: Недостаточно прав» (в Network — ответ **403**).
6. Выйти, **войти под сотрудником** → появились форма и кнопки «Изменить»/«Удалить» → добавить, изменить и удалить товар (**успешная операция**).

Проверка через терминал (Windows — `curl.exe`, в одну строку):
```bash
curl.exe http://localhost:3000/api/products
```
→ `401 Нет токена` — без токена доступа нет.
