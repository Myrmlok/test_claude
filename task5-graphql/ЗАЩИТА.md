# Шпаргалка к защите — задание №5

## Главное в двух словах
- **GraphQL** — язык запросов к API: клиент сам указывает, какие поля ему нужны, и получает ровно их. Все запросы идут на один адрес.
- **Apollo Server** — библиотека для создания GraphQL-сервера на Node.js. **Apollo Sandbox** — страница в браузере для отправки запросов.
- **RabbitMQ** — брокер сообщений: одна программа кладёт сообщение в **очередь**, другая забирает его оттуда, когда сможет.

## Вопросы и ответы

### GraphQL

**Чем GraphQL отличается от REST?**
В REST много адресов (`/books`, `/books/1`, `/authors`), и сервер сам решает, какие поля отдать. В GraphQL один адрес, а клиент в запросе перечисляет нужные поля, в том числе связанные объекты (книга вместе с автором), — всё за один запрос.

**Что такое GraphQL-схема?** (файл `src/schema.js`)
Описание всех типов данных и операций API: какие есть типы, их поля и что можно запросить. `!` означает «обязательно, не null», `[Book!]!` — список книг.

**Какие типы у нас есть и как они связаны?**
`Author` (id, name, country, books) и `Book` (id, title, year, author). Связь «один ко многим»: у автора много книг, у каждой книги один автор. В данных книга хранит `authorId`.

**Что такое Query?**
Операция **чтения**. У нас: `books` — список книг, `book(id)` — книга по id, `authors`, `author(id)`.

**Что такое Mutation?**
Операция **изменения** данных. У нас `addBook(title, year, authorId)` создаёт книгу.

**Что такое резолвер?** (файл `src/resolvers.js`)
Функция, которая возвращает данные для конкретного поля схемы. Например, `Query.books` возвращает массив книг, `Mutation.addBook` добавляет книгу.

**Что такое резолвер связи?**
Резолвер поля, которое ведёт к другому типу:
- `Book.author` — по `parent.authorId` находит автора книги;
- `Author.books` — находит все книги автора.

`parent` — объект, у которого GraphQL запрашивает поле (для `Book.author` это текущая книга).

**Какие аргументы получает резолвер?**
`(parent, args)`: `parent` — родительский объект, `args` — аргументы из запроса (например, `id` в `book(id: "3")`).

### RabbitMQ

**Что такое брокер сообщений и зачем он нужен?**
Посредник между программами. Отправитель не ждёт, пока получатель обработает сообщение: он просто кладёт его в очередь. Так сервисы становятся независимыми: если получатель выключен, сообщения дождутся его в очереди.

**Что такое очередь?**
Хранилище сообщений внутри RabbitMQ, работает по принципу «первым пришёл — первым ушёл». Наша очередь называется `book_created`.

**Что такое Producer?** (файл `src/rabbit.js`)
Тот, кто **отправляет** сообщения. У нас это GraphQL-сервер: в резолвере `addBook` после создания книги вызывается `publishMessage(...)` → `channel.sendToQueue(...)`.

**Что такое Consumer?** (файл `src/consumer.js`)
Тот, кто **получает** сообщения. Это отдельная программа: подписывается на очередь через `channel.consume(...)`, выводит данные книги в консоль и подтверждает обработку через `channel.ack(msg)`.

**Зачем `ack`?**
Подтверждение, что сообщение обработано. Только после этого RabbitMQ удаляет его из очереди. Если Consumer упадёт до `ack`, сообщение не потеряется.

**Что значит `durable: true` и `persistent: true`?**
Очередь и сообщения сохраняются на диск и переживают перезапуск RabbitMQ.

**Как сообщение передаётся?**
Объект превращаем в JSON-строку, а затем в байты (`Buffer.from(JSON.stringify(...))`). Consumer делает обратное: `JSON.parse(msg.content.toString())`.

**Что за порты 5672 и 15672?**
5672 — порт для подключения программ (протокол AMQP). 15672 — веб-панель управления RabbitMQ.
